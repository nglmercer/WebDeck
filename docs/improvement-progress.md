# Improvement implementation progress

The full scope is [improvement-plan.md](improvement-plan.md). Implementation is in progress; this document does not replace or narrow that plan. The [completion audit](improvement-audit.md) records requirement groups, evidence, and remaining verification.

## Delivered changes

- Save generations preserve edits made while a request is pending and advance the persisted revision. Done refuses to leave editing if later edits still need saving. A successful write remains reported as saved when display refresh fails.
- Unapplied button edits and staged folder changes participate in native before-unload protection. Comparing against the normalized dialog baseline avoids a warning merely for opening an existing button. Explicit cancellation still discards the staged edit.
- Button placement changes remain staged until Apply. Neighbor swaps happen in the editor controller at commit. Folder/button mutations preserve fixed positions and unknown extensions.
- Boot requests have generation protection; reload and backup import protect dirty drafts. Malformed folder hashes recover. Edit actions now enter editing. Pairing input survives failed authentication.
- Post-save refreshes have their own generation so late boot/translation results cannot replace a newer refresh, and obsolete failures cannot publish a misleading notice. Two unit regressions cover these races. Browser tests verify declined reload preserves an unsaved settings draft and the native before-unload warning preserves it when dismissed.
- Assets are deduplicated, reused, and revoked on replacement/disposal. A cache-wide four-request limit applies across overlapping loads; obsolete queued work is skipped. A deferred-request regression verifies that overlap never exceeds four active requests. Stale loads cannot publish their URLs.
- HTTP, realtime, schema interpretation, ID generation, and metric polling have separate owners. Realtime disconnect still rejects pending observers without replaying commands. Metric failures mark readings stale.
- Deck rendering, editor toolbar, button dialog, searchable actions, appearance settings, integrations, devices, and modal behavior are extracted from App. The editor controller owns mutations. Session loading, navigation, gestures, button drafts, execution feedback, pairing, and backup workflows now have separate owners under feature folders; App composes those owners.
- Deck styles are owned by `features/deck/deck.css` with global theme hooks shared by previews. Feedback, token disclosure, toolbar, button dialog, modal controls, and schema-field layout styles are component-scoped; obsolete edit-option/layout rules are removed. Save-status styling uses a stable class across translations. Theme acceptance verifies an uploaded border rule overrides tile defaults.
- Browser keyboard-only editing walks Tab/F1/Escape/Q/Space through dialog, Apply, Save, and Done, checking focus restoration, reduced-motion press behavior, and zero command execution. Typography/motion/success/warning tokens now support explicit text-bearing outcome badges and integration-change warnings; default feedback pairs exceed 4.5:1 contrast.
- Shared dark design tokens, touch sizing, reduced motion, visible edit/save state, action search, and friendly action names are implemented. Mobile edit controls fit tiles; folder tools appear above the grid.
- Native modal dialogs cycle Tab explicitly and restore focus. Numeric generic fields reject invalid values; arbitrary JSON fields preserve value types.
- Simultaneous errors and notices stack without overlap and remain independently dismissible. Dismissal controls are at least 44×44 pixels; a 360 px browser regression verifies both messages, bounds, and independent dismissal.
- Device loading distinguishes loading, failure, and an empty list, with a deferred-request browser regression verifying failure and retry. Device-local errors use the shared translation lookup. One-time tokens have copy feedback and an explicit hide action.
- Execution disposal clears feedback timers and rejects later calls; pending completion after disposal cannot schedule feedback or replay a command, covered by two unit regressions.
- Device refreshes ignore stale completions and disposal closes token disclosure. Delayed clipboard completion cannot clear a newer approval; a browser regression exercises two approvals with a pending copy. Revoke requests have per-device working guards.
- Rust server routes are split into auth, configuration, commands, devices, assets, integrations, metadata, and realtime. Native handlers are split into desktop input, processes, metrics, network, audio, system, and existing specialized helpers. Authorization and the typed dispatcher remain central.
- Configuration reads and writes require local administrator access; a supplied device token never inherits loopback administrator status; paired settings grants cannot retrieve integration credentials or action source. Boot only advertises editing to local administrators.
- Integration status and OBS checks have additive canonical v2 contracts. Checks require local Settings access, allow at most two simultaneous probes, use a three-second budget, and read version information only; Spotify reports stored authorization without claiming live connectivity. Router tests cover redaction and paired-token denial.
- Folder deletion/undo now has browser coverage comparing the complete configuration/revision before and after recovery. Dirty backup replacement decline/retry compares the full downloaded draft and verifies a separate Save is required before host publication.
- Backup preview, invalid input, cancellation, separate save, retained extensions, and shortcut duplicate/delete/undo have browser regressions. File inspection has a 16 MB limit and stale completion guard.
- Applying or duplicating a button draft refreshes deck assets before host save. Browser coverage verifies an uploaded icon is visible while the button remains absent from persisted configuration. Missing icons show a placeholder instead of raw asset identifiers.
- Live button preview, bounded numeric appearance fields, local command outcomes, disabled-action reasons, a dismissible first-use hint, settings section navigation, backup preview/apply, duplication, and guarded deletion recovery are implemented.
- Integration field edits and settings disposal invalidate pending authorization/probe results. Spotify continuation links publish only for the unchanged saved attempt; a late initial status snapshot cannot overwrite an explicit OBS check. Deferred-response browser regressions cover both races and deliberate reauthorization with updated credentials.
- Permissions use plain-language labels and human-readable expiry. Copied tokens clear from the UI. Integration secrets have explicit reveal controls; Spotify authorization uses an explicit continuation link after saving.
- Interface copy uses 372 stable keys, English fallback, reactive per-application lookup, and placeholder formatting. Spanish adds 221 core keys; other missing locale keys retain English. Saving language changes refreshes UI copy while keeping configured content and action IDs intact. CI validates resources, placeholders, and static markup.
- Pairing, empty, offline, and conflict screenshots exist at all three widths. Pairing retains invalid input and passes axe checks. Native Chromium touch hold/release opens controls without execution; a later tap executes exactly once. Real Chromium 200% zoom, long copy, missing fallbacks, dialog bounds/Apply reachability, and F1 overlay isolation have acceptance coverage.
- OS entropy failures now propagate through identifier/token generation, approval, OAuth state, asset/storage temporary paths, package/update staging, and console requests. Wayland keyboard runtime initialization returns a normal error instead of panicking. The completion audit classifies remaining runtime assertions and records unverified failure injection.
- Malformed network prefixes fail closed without subtraction overflow, covered by IPv4/IPv6 boundary tests.
- Process and audio resources have explicit owners that close before shutdown drains their resources. Managed children clean up on timeout, wait failure, and drop; Unix process tests verify leader reaping and closed-owner rejection. Audio outputs are prepared while paused before playback starts; live audio verification remains pending.
- Desktop `Open` and tray browser launchers have at most 64 waiters. Waiter creation precedes process spawning; direct children are reaped on exit. Handoffs remain outside managed-process shutdown to preserve external applications. Three Unix regressions cover reaping, spawn failure/capacity release, and a pipe-controlled handoff surviving native-owner shutdown before exit. Live Windows desktop handoff remains unverified.
- Script-file reads stop at 64 KiB plus one byte and reject oversized or invalid UTF-8 sources. Windows process-tree cleanup uses a two-second helper deadline; live Windows cleanup verification remains pending.
- Linux `pactl` queries and `grim` pixel capture use bounded concurrent stdout/stderr reads (1 MiB/64 KiB) and a shared five-second deadline. Overflow, pipe failure, and timeout drop the managed child and clean up its process group. Tests cover both pipes, exit status, continuous output overflow, and stalled output; live audio/capture remains unverified.
- HTTP/realtime token checks and network-policy snapshot reads now share separate four-slot blocking authorization admission. Device listing uses bounded disk admission; realtime metrics use the query pool. Saturation fails closed before effect admission, with router coverage for independence and recovery. Fresh grant-file reads preserve revocation behavior.
- Configuration reads/writes, asset reads/uploads, and device approval/revocation move disk work off async request workers. A four-slot per-server admission pool bounds these tasks; authorization precedes admission. Cancellation retains the slot until the blocking task completes, covered by a channel-coordinated regression. Other metadata and integration blocking paths remain under audit.
- Boot snapshots/redaction, translation file reads, and configured-button resolution also use bounded disk admission; HTTP and realtime share the same resolution helper. Spotify authorization exchange has a ten-second deadline and token persistence runs in the disk pool after releasing the token lock. A saturated-pool router regression verifies authentication still precedes admission and direct commands remain independent.
- Metrics and audio enumeration use a separate two-slot per-server blocking query pool. Its saturation cannot consume disk or command capacity, covered by a router regression. Blocking OS calls retain their slot until completion; bounding admission does not make an OS call interruptible.
- Linux endpoint enumeration and switching now share the remaining Audio budget, with a regression rejecting denied/expired contexts before host access. Restart operations recheck the context between stopping and starting a replacement. Native budget inventory lists the remaining fixed-wrapper families.
- Capture now passes the absolute deadline through grim and portal stages, rechecks before fallbacks and after sampling, and rejects expired cursor/portal/helper access. Color-picker clipboard writes recheck the execution context. Portal temporary files are removed even when reading them fails or the deadline expires before the read.
- Power/screensaver/firewall, foreground, kill, desktop restart, and Linux volume subprocess helpers now use the remaining absolute deadline with the existing five-second ceiling. Expired helper requests return the budget error before spawning, covered by a regression that invokes no host effects.
- Wayland keyboard/text now use the remaining absolute command deadline with the existing twenty-second ceiling; expired requests reject before runtime/portal access. Direct key presses check expiry while retaining key-release cleanup. Session-close cleanup retains its independent one-second ceiling.
- OBS/Spotify wrappers now clamp to remaining Network budget and recheck policy before effects. Linux MPRIS and mute use remaining Audio budget. Expired/denied media contexts have a regression rejecting them before bus access; no native effect retry is introduced.
- Application-volume helpers consume the shared execution deadline between streams rather than granting every stream a new budget. Windows rechecks policy before per-stream effects; Linux clamps each subprocess to remaining time. Network and shell timeouts are clamped to the remaining action budget. Context regressions cover permission denial, timeout clamping, expired deadlines, and nested-budget rejection; live volume verification remains pending.
- Folder-navigation acceptance waits for saved state and editor exit before invoking navigation; five repeated runs and the complete 29-case suite passed. Acceptance uses observable readiness; the remaining socket timer is a terminal-result failure deadline rather than a timing sleep.
- Usage polling setup no longer tracks refresh-result state; a response cannot recreate the interval and trigger immediate repeated polling. A unit regression verifies cadence, no overlap, and disposal.
- Browser profiling records comparable 48/1,024-button decks, fresh contexts, shared uploaded icons, boot/load times, and polling. Each deck fetches its repeated icon once; two periodic requests are observed before settings, followed by zero new requests during a 1.5-second settings window. Bundle budgets (225,000 raw / 69,000 gzip bytes) are enforced in CI. Local UI p95 ceilings (350/600 ms) have 50% baseline headroom rounded to 50 ms; CI does not enforce machine-sensitive timing. Negative timing-budget injection is rejected. [Browser evidence](v2/evidence/improvements/browser-performance.json).
- Frontend formatting is checked in CI. Performance reports support a separate output path so new measurements preserve historical evidence.
- Opt-in command diagnostics emit allowlisted terminal metadata from the accepted execution owner: SHA-256 request-ID fingerprint, capability category, duration, outcome, and canonical error code. Raw IDs, payloads, headers, outputs, and free-form errors are excluded. A dedicated writer and bounded 256-record queue keep stderr backpressure outside execution; enqueue is non-blocking and saturated records are dropped. A controlled blocked-sink test verifies bounded admission and continued producers. Records are best effort and may be lost on process exit. Unit redaction coverage and `node tools/validation/diagnostics.mjs` HTTP smoke passed; CI runs the smoke. Requests rejected before the executor have no executor event.

Smoke and rollback reports identify the same archive digest; this is development-package evidence, not release or live desktop verification.
